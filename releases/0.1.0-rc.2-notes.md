# Fairway XMP 0.1.0-rc.2

Staged release notes. RC 2 is not published; candidate CI and exact-installer acceptance are still required. This release is intended for real project/classroom testing before 0.1.0 stable.

## Changes since RC 1

- Open existing SQLite project files directly in the desktop Data browser with MySQL stopped. Browse/edit rows and tables, run SQL, remember recent files, and create consistent SQLite backups, including committed WAL data. Missing paths never create replacement databases.
- Inspect indexes and incoming/outgoing foreign keys for MySQL and SQLite. Create ordinary/composite unique indexes and remove supported indexes with confirmation and a protective backup. Primary, constraint-owned, advanced and relationship-dependent indexes remain protected, including SQLite references that reorder composite columns. Foreign-key editing stays in SQL.
- MySQL SQL execution now rejects unfinished transactions instead of reporting success before connection shutdown rolls them back. Finish COMMIT or ROLLBACK in the same run. MySQL runs all submitted statements and displays the first ten result sets, with an explicit notice when results are omitted; errors in later statements are still reported. SQLite retains its pre-execution ten-statement limit.
- A broken view or unreadable table leaves the database catalog, other tables and SQL repair tools usable, without showing old rows under the failed selection.
- Mac candidates use native login-keychain SSL trust installation/removal and a bundled, Developer ID signed background helper for local `.test` addresses. macOS requires one-time background-helper approval; subsequent address changes reuse it. Authorization handoffs and in-process certificate removal improve prompt focus. Actual prompt behavior and approved-helper upgrades require device acceptance for the candidate.
- Site forms use shorter help with keyboard-accessible tips. New document roots get a simpler welcome page; existing/custom `index.php` files are preserved.
- Operation results stay in fixed, dismissible notifications without scrolling the page or taking keyboard focus. The sidebar folds to icons, pages use the available width, and the data grid uses the remaining window height.

## Installation and updates

Install only the verified candidate/release files for your platform. Runtime versions and pinned inputs are unchanged from RC 1. All sites, CLI PHP and Composer still share the selected global PHP version; per-site PHP remains outside this release.

Before a manual update, back up databases, stop services, close project database users, and quit Fairway from its menu bar/tray. Keep coursework, settings and backups. On Mac, use the regular installer and keep the installed app at `/Applications/Fairway XMP.app`; an approved background helper must also pass the upgrade/removal acceptance checks. Standalone permission prototypes should be unregistered using their documented cleanup before moving or deleting them.

Signed desktop updates can offer RC 2 after explicit preview-feed promotion. Linux updates remain manual. Exact-installer acceptance precedes publication; the human in-app update/restart check follows publication and feed promotion on both Windows and Mac. No existing RC 1 acceptance is reused for changed RC 2 bytes.

SQLite files are edited in place. Their backups are separate from the MySQL environment/update backup; use **Back up SQLite file** and verify restoration before destructive administration. SQL changes execute immediately and do not automatically create backups. Cancellation cannot undo earlier committed statements.

## Known limitations retained

- Windows installers have no Authenticode signature and may display unknown-publisher/SmartScreen warnings. Cryptographic updater signatures remain required; Mac app/installer Developer ID signing, notarization and stapling remain required.
- Windows PHP 8.0/8.1 dependency build/patch provenance remains unverified. These versions are unsupported legacy compatibility options; PHP 8.5 remains the default.
- On non-UTF-8 Windows system code pages, MySQL CLI backup/export requires supported ASCII schema/table identifiers. Errors preserve data and block an update whose required backup cannot complete. Normal Unicode row/query handling remains supported. Existing MySQL filesystem/code-page restrictions still apply.
- Linux remains the x86_64 terminal edition on glibc 2.35+; macOS requires Apple Silicon and macOS 15+; Windows requires supported x64 Windows 10/11. Native dialogs, helper lifecycle and installer behavior require actual supported-device acceptance.

See [Data browser](../docs/data-browser.md), [candidate acceptance](../docs/beta-acceptance.md), and [RC preparation](../docs/rc-preparation.md). Published RC 1 artifacts, evidence and feeds remain unchanged by this source preparation.
