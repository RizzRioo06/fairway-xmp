# Sites, domains, and HTTPS acceptance

Run this on an installed candidate on each supported platform: macOS, Windows, and the Linux terminal edition. Use a disposable local account or machine. Record the OS, browser versions, installer hash, and build commit. These checks must use the OS resolver and normal browser trust; do not use `curl --resolve`, `--cacert`, or `-k` as substitutes.

1. Ordinary usage: with no sites, create `fairway/www/plain/index.php`, start Fairway, and open `http://127.0.0.1:8800/plain/`. Confirm startup, Start all, and Stop all never ask for OS elevation and leave the hosts file and trust store unchanged.
2. Outside the document root, create `~/code/shop/public/index.php` that echoes `$_SERVER['REQUEST_URI']`, plus `~/code/shop/.env`. Open **Sites** and choose **Add site** (Linux: `fairway site add shop ~/code/shop/public --index`), pick `public` with the folder picker, select **Laravel / front controller** under **App type**, read the hosts explanation, and approve the OS request. Open `http://shop.test:8800/courses/1` in a normal browser: it must reach `index.php`. Confirm `/.env` and `../.env` paths are not served and that only `shop.test` was added inside Fairway's marked hosts block.
3. Decline: add a second site and cancel the OS request. Confirm the site stays listed as "Address setup needed", **Set up addresses** appears, and HTTP for `shop.test` still works. Retry and approve.
4. Edit: rename the second site's domain. Confirm one approval replaces the old hosts entry with the new one and the old domain stops resolving. Edit only the name or web root and confirm no OS prompt appears.
5. Enable HTTPS for `shop` after reading the trust explanation. Open `https://shop.test:8443/` in the platform's normal browsers without ignoring certificate errors: Safari and Chromium on macOS, Edge and Firefox on Windows, Chromium and Firefox on Linux. Record whether each browser trusts the certificate. A browser warning is a failure to investigate, not a pass. Cancel the trust prompt once and confirm HTTPS stays off with an error, HTTP keeps working, and retrying works.
6. Turn HTTPS off. Confirm HTTP still works and **Remove certificate trust** appears; use it and confirm the trust store no longer lists Fairway's CA.
7. Move `~/code/shop` away. Confirm the site shows as unavailable without being removed, Nginx still serves other sites, and editing the web root recovers it. Remove the site and confirm its folder and files remain and its hosts entry is gone, while unrelated hosts entries are untouched.
8. Configuration failure: make the web root unreadable or otherwise force `nginx -t` to fail while saving. Confirm the error is shown, the previous site list is kept, and `http://127.0.0.1:8800/` keeps working.
9. Uninstall while keeping data. On macOS, test both the interactive path and `--yes-keep-data`; on Windows, test the normal and silent NSIS paths; on Linux, run the bundled uninstaller. Confirm Fairway's hosts block and CA trust are gone, while sites, databases, and backups remain. Reinstall and confirm sites are listed with HTTPS off and **Set up addresses** offered. On macOS, also test the optional delete-data path after trust cleanup.

10. Desktop readiness and layout: with services stopped, add/edit a site and confirm the result says it was saved, without claiming it is ready. Start the web server from Sites and confirm PHP/Nginx start while MySQL stays stopped. Confirm Open becomes available, and editing an HTTPS site reports its secure URL. At 820×650, verify long names, URLs, paths, the actions menu, and the form footer remain usable without horizontal scrolling. Copy a URL and open the web root in the file manager.
11. Desktop site terminals: register a public root outside coursework with spaces/Unicode in its path. Open a terminal in its web root, then in its app folder; verify each actual working directory. Return to Sites and select an already-open location; confirm the same tab is focused and output remains. With two tabs open, request another location and confirm neither shell is replaced. Delete/move the registered root and verify new sessions fail without interrupting existing sessions.
12. Saved-list recovery: with Fairway stopped in the disposable account, keep a copy of sites.json and replace it with invalid JSON. Launch and confirm Sites shows a load error with details and retry, disables Add site, and never says "No sites yet". Confirm the basic localhost server still works and the invalid file is preserved. Restore the copy, retry, and confirm the list returns. Linux status and dashboard must also show the load error.

Retain the browser result, hosts-file before/after diff with unrelated entries redacted, trust-store verification, and installer lifecycle result with the candidate. Do not merge based only on source tests or the smoke test's forced DNS/certificate options.
